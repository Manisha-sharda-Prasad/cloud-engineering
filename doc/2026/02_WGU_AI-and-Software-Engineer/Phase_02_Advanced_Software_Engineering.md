## 2. Comprehensive Study Topics

### 2.1 Software Development Life Cycle (SDLC)
- **Phase Breakdown:**
  1. **Planning:** Feasibility analysis, scope definition, resource allocation.
  2. **Requirements:** Stakeholder analysis, functional/non-functional requirements gathering.
  3. **Design:** High-level architecture, low-level component design, UI/UX wireframing.
  4. **Implementation:** Code construction, peer reviews, static analysis.
  5. **Testing:** Unit, integration, system, and user acceptance testing (UAT).
  6. **Deployment:** Delivery to staging/production environments.
  7. **Maintenance:** Bug fixes, security patching, performance monitoring.

### 2.2 Traditional vs. Modern Methodologies
- **Waterfall Methodology:**
  - Sequential, phase-gated approach.
  - *Pros:* Clear documentation, predictable outcomes for fixed scope, well-defined milestones.
  - *Cons:* Inflexible to change, late delivery of working software, high risk late in project.
  - *Ideal Use Cases:* Regulatory/safety-critical software, fixed-scope projects with unchanging requirements.
- **Agile Methodology:**
  - Iterative and incremental delivery guided by the Agile Manifesto.
  - Adaptive planning, early delivery, continuous improvement.

### 2.3 Agile Frameworks: Scrum & Kanban
- **Scrum Framework:**
  - *Roles:* Product Owner, Scrum Master, Developers.
  - *Artifacts:* Product Backlog, Sprint Backlog, Increment.
  - *Events:* Sprint Planning, Daily Scrum (Standup), Sprint Review, Sprint Retrospective.
  - *Estimation:* User Stories, Story Points (Fibonacci scale), Velocity tracking.
- **Kanban Framework:**
  - Visualizing work on a Kanban Board.
  - Work-in-Progress (WIP) Limits to prevent bottlenecks.
  - Continuous flow, Cycle Time, and Lead Time focus.

### 2.4 Project Management & Engineering Metrics
- **PM Constraints:** The Iron Triangle (Scope, Schedule, Budget) + Quality & Risk.
- **Agile & Engineering Metrics:**
  - *Velocity:* Story points completed per sprint.
  - *Burndown / Burnup Charts:* Tracking remaining work vs. elapsed time.
  - *Cycle Time:* Time taken from work start to work completion.
  - *Lead Time:* Time taken from user request creation to delivery.
  - *Defect Rate / Defect Density:* Bugs found per KLOC (thousand lines of code) or per story point.

## 3. Methodology Selection Framework

| Selection Criterion | Waterfall | Scrum (Agile) | Kanban (Agile) |
| :--- | :--- | :--- | :--- |
| **Requirements Stability** | Highly stable & fixed | Evolving / Frequently changing | Continuous / Unpredictable streams |
| **Project Scope** | Well-defined upfront | Large, modular, feature-based | Operational support, maintenance |
| **Client Involvement** | Start & End phases | Continuous (every 2–4 weeks) | Continuous feedback |
| **Risk Management** | Upfront risk planning | Iterative risk mitigation | Immediate bottleneck resolution |

## 4. Phase Deliverable
**Project:** SDLC & Project Strategy Blueprint  
**Requirement:** For a target enterprise software concept (e.g., E-Commerce Subscription Management Platform):
1. Document the complete SDLC phase plan.
2. Formulate a comprehensive Agile/Scrum project management plan (Roles, 2-sprint Backlog with User Stories and Story Points).
3. Draft a **Methodology Justification Document** evaluating why Agile/Scrum was selected over Waterfall based on Scope, Budget, Timeline, and Risk.
4. Define a metrics dashboard tracking Velocity, Cycle Time, and Defect Density.
